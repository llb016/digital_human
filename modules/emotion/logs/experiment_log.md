## 6.2 配置化：新增可调参数（写入根目录 config.yaml）

原有键 `emotion_threshold: 0.6` 保持原值、原语义不变（本模块只读取并对外暴露，不在 predict 内二次过滤，避免两处各判一次阈值）。

| 配置键 | 当前值 | 含义 | 调参影响 |
| --- | --- | --- | --- |
| emotion_threshold | 0.6 | 主程序采纳阈值（原有键） | 由主程序/队长使用；本模块通过 `classifier.confidence_threshold`、`is_confident()` 暴露 |
| emotion_confidence_base | 0.5 | 置信度起始值 | 影响所有非未知结果的置信度起点 |
| emotion_confidence_coef | 0.1 | 每 1 分的置信度增量 | 只影响置信度，不影响标签（见 6.6 实验） |
| emotion_confidence_max | 0.95 | 置信度上限 | 压低上限可减少高分误采纳 |
| emotion_unknown_confidence | 0.3 | 无情绪命中时的置信度 | 影响"未知"是否被主程序采纳 |
| emotion_min_score | 1 | 情绪判定阈值：最高分低于该值判为未知 | 提到 2 会大幅降低准确率（50 条测试集 70% -> 46%） |
| emotion_score_epsilon | 1.0e-6 | 并列判定容差 | 仅影响分数近似相等时的优先级裁决 |
| emotion_weights | {愤怒: 2, 悲伤: 2} | 关键词权重覆盖（未列出的情绪权重为 1） | 提高某类权重会挤占其他类的判定 |
| emotion_labels | [开心, 平静, 焦虑, 悲伤, 愤怒, 孤独, 疲惫, 未知] | 情绪标签集（声明给全队） | 成员2 用其做标签漂移观测；主程序据此校验 |

配置读取策略（为避免"配置没生效但看不出来"）：

1. 从模块目录向上逐级查找仓库根目录 `config.yaml`（兼容不同的目录布局）；
2. 缺文件 / 缺键 / 非法值（非数值、越界、权重写成非法项、标签集写成标量）→ 回退内置默认值并记录提示；

## 6.3 浮点比较修复：改造前后对比

```python
# 改造前（emotion_classifier.py）
max_score = max(scores.values())
for emotion in priority:
    if scores[emotion] == max_score:      # 浮点直接用 == 比较
        break

# 改造后
max_score = max(scores.values())
emotion = None
for candidate in self.priority:
    # 差值判断：分数近似相等即视为并列，交给优先级裁决
    if candidate in scores and abs(scores[candidate] - max_score) < self.score_epsilon:
        emotion = candidate
        break
```

复现实验（自测用例 4，`python emotion_self_test.py`）：

```
权重构造：焦虑 = 0.1 + 0.2 (= 0.30000000000000004)，愤怒 = 0.3
输入文本：我又焦虑又生气
改造前（== 比较）   ：预测 焦虑   <- 浮点噪声让"并列"判定失效，优先级被绕过
改造后（差值比较） ：预测 愤怒   <- |0.30000000000000004 - 0.3| = 5.55e-17 < 1e-6，按优先级裁决
```

结论：整数权重（默认配置）下两者结果相同；一旦权重来自配置且是小数，`==` 会让优先级策略随机失效，差值比较消除了这一隐患。

| 5 | 愤怒 | 未知 | 0.3 | 别人一直打断我讲话，让我很不舒服 |
| 6 | 孤独 | 焦虑 | 0.6 | 想找个人聊天，但是不知道找谁 |
| 7 | 孤独 | 未知 | 0.3 | 身边认识很多人，但还是觉得很孤单 |

| 9 | 疲惫 | 未知 | 0.3 | 最近睡眠不好，总感觉没有精神 |
| 10 | 平静 | 未知 | 0.3 | 今天阳光很好，我坐在窗边喝茶 |
| 11 | 平静 | 焦虑 | 0.6 | 现在感觉挺放松的，没有什么压力 |

错误归因：

1. **平静 vs 未知（7 条，占比最高）**：规则法没有"平静"的正向信号，无关键词就判未知；案例 10~13、15 都属于这一类。
2. **否定/隐含表达**：案例 11「没有什么压力」被"压力"命中判成焦虑，属于否定语义缺失。
3. **词义交叉**：案例 4「加班」触发疲惫，压过"烦"（愤怒）；案例 2「朋友分开」同时命中孤独与悲伤。
4. **词典覆盖不足**：案例 9「睡眠不好」未命中疲惫词表；案例 8「一点力气都没有」与词表「没有力气」表述不一致。

## 6.6 调参对比实验（emotion_param_sweep.py）

命令：`python emotion_param_sweep.py`（只覆盖内存中的配置，不改任何文件）

```
基线（config.yaml 原值）                       35/50  70.00%
判定阈值 min_score=2（更保守）                  23/50  46.00%  (-24 个百分点)
                                         变化类别: 孤独 4->1、平静 1->0、开心 6->3、焦虑 6->4、疲惫 4->1
判定阈值 min_score=0（不设阈值）                35/50  70.00%  (+0 个百分点)
置信度系数 coef=0.2（只影响置信度）              35/50  70.00%  (+0 个百分点)
权重：愤怒 3 / 悲伤 2                         35/50  70.00%  (+0 个百分点)
权重：焦虑 2 / 悲伤 2                         34/50  68.00%  (-2 个百分点)
                                         变化类别: 开心 6->5
```

结论与采纳：

1. `emotion_min_score` 保持 1：提高到 2 后准确率掉到 46%（大量单关键词样本被推成未知）。
2. `emotion_confidence_coef` 只影响置信度、不影响标签：适合用来调节主程序 `emotion_threshold` 的采纳率，标签精度不受影响。
3. `emotion_weights` 维持 {愤怒: 2, 悲伤: 2}：把"焦虑"权重提到 2 会吃掉开心样本（-2 个百分点），收益不明显。
4. 所有参数均可通过 `--set` 做对比实验，确认最优后再写入 config.yaml，全程不改源码。

## 6.7 已知问题与下一步（不在本次返修范围内）

1. 平静类别缺少正向特征（17%），"无关键词"与"平静"在规则层面无法区分 —— 下一步考虑引入词表外特征或多分类模型。
2. 只有正向词、没有任何情绪关键词的文本仍返回未知（如「终于获得奖学金了」）：该顺序影响基线准确率，本次刻意保留不变（自测用例 3 已固化该行为）。
3. 否定语义（「没有什么压力」）尚未处理，计划在下一轮迭代加否定前缀检测。
